# Domain docs

This repo has one domain context. Before exploring the codebase, read the root `GLOSSARY.md` and the ADRs in `docs/adr/` that cover the area you’re working in. If a relevant file is absent, continue with the available documentation.

Use glossary terms in issues, proposals, and tests. Note genuine gaps for the domain-modeling skill. If your work conflicts with an ADR, identify the decision and explain why it needs revisiting.
